# 使用手册 · md-rewrite-engine v0.3.0（执行者选择器 + 本体主控）

> 日期：2026-08-16｜给用户（或新会话）照着用。

---

## 一、这套东西怎么运转（一句话）

**你丢一份转写给我 → 我在对话里亲自重排（带全局上下文）→ 调脚本跑 GLM 质检/评分 → 我复核修补 → 输出 AI 友好笔记**（转写原文外置到源文件；笔记自动带 📑 篇内目录，脚本后处理生成）。

## 二、怎么跑一份转写

1. 把转写（清洗后 md / 转写 json）给我，或告诉我路径。
2. 我确认执行者配置（第 3 节）。
3. 我按编排手册（`docs/orchestration-manual.md`）10 步跑：读全文→抽概念地图→分块→我逐块重排→自查→对账→GLM质检/评分→我复核→整体审→输出。
4. 输出：笔记.md + 源数据/转写.md，我会告诉你位置 + 质检摘要（哪些问题已修/哪些挂起）。

## 三、执行者配置（谁做哪个环节）

默认（`configs/executors.yaml`）：
| 环节 | 执行者 |
|---|---|
| rewrite 重排 | 本体（我） |
| reconcile 对账 | 本体（我） |
| quality 质检 | GLM（glm-4.5-air） |
| scoring 评分 | GLM（glm-4.5-air） |

**改配置**：直接说"改执行者"→ 我问你 4 环节各用谁（claude/glm/deepseek/anthropic）→ 我更新配置生效。
**密钥**：存 `.env`（GLM_API_KEY / DEEPSEEK_API_KEY / ANTHROPIC_AUTH_TOKEN），安全不进 git。

## 四、质量保障（为什么不跑偏）

- **fail-closed 门禁**：机械对账/质检不达标 → 不能"通过"。
- **每块独立 4 次修补**：单块最多修 4 次，仍不过 → 挂起待人工（不死循环）。
- **原文保护**：事实信息原样保留 + 机械对账兜底（覆盖率 ≥90%），不修没。
- **详细度写死**：6 件套 + 费曼 4 角度 + 重要展开 + 口语可丢（见 `docs/prompt-family-p1-p5.md`）。

## 五、换执行者 / 以后复用

- **换执行者**：跟我说"quality 用 DeepSeek"→ 我改 executors.yaml → 生效。
- **换会话复用**：新会话照 `docs/orchestration-manual.md` + `docs/capability-functions.md` 跑即可（脚本函数库 + 我的编排步骤都在文档里）。

## 六、验收参照

产出对标旧工作流详细度（NoteBooks 下 100KB 版）：6 件套齐全、费曼 4 角度、不丢关键内容、AI 能照着教。
