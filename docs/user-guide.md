# 使用手册 · md-rewrite-engine v0.4.6（人机接力 + 五指标门禁）

> 初版：2026-08-16｜最近更新：2026-10-01（补第 0 步过滤 + 五指标门禁 + 丰富度铁律）｜给用户（或新会话）照着用。

---

## 一、这套东西怎么运转（一句话）

**你丢一份转写给我 → 我先过滤源（去 OCR 噪音，出对账基准）→ 我在对话里亲自重排（带全局上下文）→ 跑机器门禁五指标 + GLM 质检评分 → 我复核修补（≤4 轮）→ 输出 AI 友好笔记**（转写原文外置到源文件；笔记自动带 📑 篇内目录）。

## 二、怎么跑一份转写

1. 把转写（清洗后 md / 图文书 full_embedded.md）给我，或告诉我路径。
2. **第 0 步 · 源前置过滤**（必做）：文字型 PDF 走 `ocr_source_filter`；MinerU 图文书走 `ebook_source_filter --keep-glm`（保留 GLM 画面理解，书里图上的知识文字在其中）→ 产出 `clean_only.md` 作对账基准。
3. 我确认执行者配置（第 3 节）。
4. 我按编排手册（`docs/orchestration-manual.md`）**10 步**跑：读全文→抽概念地图→分块→我逐块重排→自查→对账→**门禁五指标 + GLM 质检/评分**→我复核修补→整体审→输出。重排时守**丰富度铁律**（内容量 1.0~1.3 倍，只展开不压缩）。
5. 输出：笔记.md + 源数据（原文全量外置），我会告诉你位置 + 门禁结果 + 质检摘要（哪些问题已修/哪些挂起）。

## 三、执行者配置（谁做哪个环节）

默认（`src/md_rewrite_engine/configs/executors.yaml`）：
| 环节 | 执行者 |
|---|---|
| rewrite 重排 | 本体（我） |
| reconcile 对账 | 本体（我） |
| quality 质检 | GLM |
| scoring 评分 | GLM |

**改配置**：直接说"改执行者"→ 我问你 4 环节各用谁（claude/glm/deepseek/anthropic）→ 我更新配置生效。
**密钥**：存 `.env`（GLM_API_KEY / DEEPSEEK_API_KEY / ANTHROPIC_AUTH_TOKEN），安全不进 git。

## 四、质量保障（为什么不跑偏）

- **门禁五指标（机器说了算）**：① 机械对账 ≥90% ② 6 件套完整 ③ 费曼示范每点 ≥2 ④ 术语变体（warning 级人工复核）⑤ **丰富度膨胀率**（≥80% 直过 / 30~80% 聚合豁免三条件 / <30% 红线）——`scripts/gate_check.py` 一键跑，不达标强制打回。
- **丰富度铁律**：源里的公式/推导/论述一条不丢，只许展开讲——专治"把完整推导压缩成提词卡"（对账 100% 也拦得住）。
- **每块独立 4 次修补**：单块最多修 4 次，仍不过 → 挂起待人工（不死循环）。
- **原文保护**：事实信息原样保留 + 机械对账兜底，不修没；源数据全量外置（换会话可溯源）。
- **结构写死**：6 件套（定义/类比/原理/示例/为什么/易错点）+ 费曼示范角度 ≥2（见 `docs/prompt-family-p1-p5.md`）。

## 五、换执行者 / 以后复用

- **换执行者**：跟我说"quality 用 DeepSeek"→ 我改 executors.yaml → 生效。
- **换会话复用**：新会话照 `docs/orchestration-manual.md` + `docs/capability-functions.md` 跑即可（脚本函数库 + 编排步骤 + 门禁标准都在文档里）。

## 六、验收参照

- **门禁全绿**（五指标，`gate_check` 实测）+ 质检无真问题。
- 对标已实际验收的三类素材样板：技术书逐章（14 章）、题库分片（97 题，Plan A 详解结构）、图文书首章（含插图块清洗）。
