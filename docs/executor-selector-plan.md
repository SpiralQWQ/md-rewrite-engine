# 执行者选择器 + 本体参与重排 · 需求与行动计划（v0.3.0 方向）

> 日期：2026-08-16｜状态：需求已确认，行动计划已认可，待实施
> 目标：让 `md-rewrite-engine` 从"纯脚本自动调 GLM"升级为"**人机接力**"——关键环节由本体（Claude 对话）亲自参与，机器干能干的，质量靠门禁兜底。

---

## 一、背景与问题

当前流水线全走 GLM 直连，实测发现：
1. **没上下文**：逐块处理，AI 看不到全局
2. **不详细**：产出知识点泛化、费曼题套通用模板
3. **结构靠机器猜**：assemble 机械切树会猜错

**结论**：全自动脚本无法达到"AI 能照着教"的详细度，需要"本体参与 + 机器兜底"混合。

## 二、目标（最终交付）

**"和旧工作流一样详细 + 一样结构化"的 AI 友好笔记**。
- 目标读者：AI 看笔记 → 教学给用户
- 验收参照：旧工作流笔记（NoteBooks 下 100KB 详细版）

## 三、执行者分工（4 环节）

| 环节 | 执行者 | 理由 |
|---|---|---|
| rewrite 重排 | **本体（我）亲自做** | 要上下文、要详细，机器写不好 |
| reconcile 对账 | **本体（我）亲自做** | 要理解内容才能查概念漏没漏 |
| quality 质检 | GLM 跑 + 我复核 | 检查类，机器先挑，我判断真伪 |
| scoring 评分 | GLM 跑 + 我确认 | 同上 |

- 配置存 `configs/executors.yaml`，密钥存 `.env`（都不进 git）
- 交互：跑之前对话询问 4 环节配置，支持混合、支持记住

## 四、长上下文处理（核心）

1. **我读全文主导**：先抽概念地图 → 定语义分块 → 建立全局脉络（机器只做超长兜底）
2. **我逐块重排**：每块带「全局地图 + 前文摘要 + 后文预告 + 块间重叠」防隔离
3. **结构不机械切树**：按 note_style_spec schema，我重排时自己建
4. **全部块做完，我通读整篇整体审一遍**（连贯/重复/遗漏/归位）

## 五、质量保障（验证/打回）

- 我自查（P2）+ 我概念对账（P3，对照概念地图）
- GLM 质检（P4）/评分（P5）→ 我复核，区分真问题/噪音
- **打回 = 带问题清单回 P1 针对性修补**（不整块重做），反馈累积
- **每块独立 4 次修补额度**；第 4 次仍不过 → 该块挂起等人工
- **原文保护**：事实信息（命令/数字/专名）原样保留 + 机械对账兜底（关键点覆盖率 ≥90%）
- **详细度写死进提示词**：重要内容展开 / 少删 / 口语可丢 / 事实保留 / 6 件套 / 费曼 4 角度

## 六、架构与边界

- **人机接力 + 我参与的插槽**：脚本沉淀机器部分，在需要我的节点留插槽（以后可换执行者）
- 完整转写附录**外置**到源文件（不干扰 AI 教学上下文）
- 可扩展列为未来期望（专注笔记质量）
- 风险高发：人机接力（A）+ 本体稳定性（B）；GLM 质检不可靠（C/D）也要防

## 七、行动计划（6 阶段）

### 阶段 1 · 执行者选择器
- **做什么**：新增 `configs/executors.yaml`（4 环节执行者 + 密钥引用）；跑之前对话询问；密钥存 `.env`
- **为什么**：这是"谁来做"的开关，全部后续的基础
- **验收**：跑一份转写，4 环节按你的选择各自走对应执行者

### 阶段 2 · 本体参与骨架（人机接力）
- **做什么**：流程加"插槽"——到 rewrite/对账/复核节点，脚本停下来把"块+上下文"给我，我做完交回继续
- **为什么**：让"我亲自做"成为可复用流程
- **验收**：脚本能"停→等我→继续"完整跑一遍

### 阶段 3 · 我主导的全局处理
- **做什么**：① 我读全文抽概念地图 ② 我定语义分块 ③ 我逐块重排（带地图/摘要/预告/重叠）④ 整体审
- **为什么**：解决"长上下文隔离"和"结构机械切树"
- **验收**：长转写产出前后连贯、无重复遗漏

### 阶段 4 · 提示词家族（P1-P5）
- **做什么**：详细度/结构/检查维度全部写死成提示词
- **为什么**：把"详细、AI 友好"变成可执行规则
- **验收**：产出 6 件套齐全、费曼 4 角度、事实信息保留

### 阶段 5 · 验证打回闭环
- **做什么**：P4/P5 不合规 → 带问题清单回 P1 修补 → 每块独立 4 次 → 挂起等人工；原文保护 + 机械对账兜底
- **为什么**：质量靠门禁，防死循环防修没
- **验收**：故意制造问题，能打回、能挂起、不死循环

### 阶段 6 · 收尾
- **做什么**：附录外置到源文件；输出笔记；写使用手册（怎么跑/配执行者/换执行者）
- **为什么**：流程可复用，不绑死当前会话
- **验收**：一份真实转写，跑出"和旧工作流一样详细 + 结构化"的笔记
