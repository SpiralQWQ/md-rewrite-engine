## 前置

1. 确认 `src/md_rewrite_engine/configs/executors.yaml`：rewrite/reconcile=claude（本体），quality/scoring=glm（默认已配）。
2. 确认密钥：`GLM_API_KEY`（质检/评分）、`ANTHROPIC_AUTH_TOKEN`（本体通道，备用）。

## 编排流程（10 步 + 第 0 步）

### 第 0 步 · 源前置过滤（PDF / 图文书两类，视频源跳过）

- **何时需要**：输入是 MinerU 解析产物时必做——否则 gate_check 机械对账被噪音拉爆，永远 FAIL。按源类型选过滤器：
  - **文字型 PDF 书**（哈希/时间戳/客户端回显/截图 OCR 残片噪音）→ `ocr_source_filter`：
    ```bash
    python -m scripts.filters.ocr_source_filter --chapter <N> --src <章节_clean.md> --out <章节_clean_only.md>
    ```
    新章节：`CHAPTER_RULES` 无该章规则时工具会报错并列出已有章节——参照已有章节补规则（noise_pre/noise_post/short_line/anchored_tokens/bare_tokens/skip_sections），**规则从该章源文件的 diff 试错中来**。
  - **图文书**（MinerU 产物含每张插图的「## 插图笔记：<哈希> / ## 图片内容（OCR） / ## GLM 画面理解」三连块）→ `ebook_source_filter`：
    ```bash
    python -m scripts.filters.ebook_source_filter --src <full_embedded.md> --out <clean_only.md> --keep-glm
    ```
    **必须加 `--keep-glm`**：书里插图上印的知识文字（如"print 是一个能将结果打印的函数"）在 GLM 画面理解块里，剔了就丢内容。实测一本图文书：全文 3210 个关键点里 2946 个来自图片块（哈希/OCR 碎片），不带 `--keep-glm` 时膨胀率还会虚高（226% vs 真实 96%）。
- **输出**：`clean_only.md` 作为第 1 步的输入与 gate_check 的 `--src` 对账源；**原始 md 仍照常外置到 源数据/转写.md**（溯源保留全量，不丢信息）。
- **视频转写源跳过**：ASR 噪音（错听/拆散数字）形态不同，由上游清洗环节处理，不走本过滤器。

### 第 1 步 · 读转写
- 拿到清洗后 md 或转写 json 的 `text`。
- 调 `read_md(path)` 或我直接读文件。

### 第 2 步 · 抽概念地图（我）
- 我读全文，抽核心概念清单（可参考 `extract_terms(text)` 的粗体术语）。
- 心里建立"全局地图"：整篇讲什么、几个大块、每块啥、前后关系。

### 第 3 步 · 物理分块（兜底）
- 调 `assemble_chunks(text)` 拿物理块（段落边界，超长兜底）。
- 若块数 > 我一次能重排的量，按概念地图**我再语义归并**。

### 第 4 步 · 我逐块重排（核心创作）
- 每块重排时带：**全局地图 + 前文摘要 + 后文预告 + 块间重叠**。
- 按 note_style_spec 建结构（概述/知识点 6 件套/词汇表/费曼 4 角度）。
- 事实信息（命令/数字/专名）原样保留；口语可丢；重要内容在原文上扩充。
- **丰富度铁律（v0.4.5，机器卡，不许自觉）**：
  - **保真底线**：源里的公式/推导/论述/机制清单，只许**展开讲**（拆步、举例、补背景），不许**合并跳步**或压缩成提词卡。「特别详细/可教学」不是风格偏好，是验收标准。
  - **扩写方向**：在源知识点框架内扩（逐公式推一遍/逐机制讲清为什么/补生活类比与常见误区），**不是**注水重复，更不是脱离源自创内容。
  - **膨胀率自检（写完每块自查）**：笔记内容量 ≈ 源内容量的 **1.0~1.3 倍**为健康区（内容量 = 剥 frontmatter/标记/空白的字符数，即 `core/verify.expansion_ratio` 口径）；明显低于 0.8 说明在压缩，回头查是不是把推导/论述跳了。
  - **口径**：膨胀率**对「过滤后源」（clean_only.md）计算**——OCR 噪音会虚高分母，用原始解析结果算会误判合格。

### 第 5 步 · 我自查（P2）
- 以"AI 读者"视角重读我写的，挑"教学会卡壳"处，当场改。

### 第 6 步 · 概念对账（P3 + 机械兜底）
- 对照第 2 步概念地图，查有没有漏知识点/概念被偷换。
- 调 `mech_reconcile(orig, rewritten)` 兜底：关键点覆盖率 <90% → 必须补。

### 第 7 步 · 门禁检查 + GLM 质检/评分（机器指标，必跑）
- **先跑 `scripts/gate_check.py 笔记.md --src 原文.md`**（v0.4.1 打回闭环落地）：一次拿到 ① 机械对账（数字覆盖率）② 6 件套完整度 ③ 费曼示范计数 ④ 术语变体（错别字机检，warning 级）⑤ 丰富度膨胀率（v0.4.5）⑥ [--score] GLM 评分。
- **术语变体（④）是软提示不拦截**：列出"源 vs 重排等长换 1 字"的可疑替换点（错字如"调度器→掉度器"、真语义改动如"子节点→父节点"），**我逐条人工复核**——真错字修掉，合法改写忽略；判定仍由 ①②③（+⑤⑥）决定。
- **丰富度（⑤）硬判定**：膨胀率 = 笔记内容量/源内容量（对过滤后源计算，剥编号前的源——章节编号是 _src_sections 的定位锚）。三区间：**≥80% 直过**（阈值取 user_prefs.yaml `expansion_ratio.general`）；**[30%, 80%) 豁免候选区**——只有同时满足「知识点覆盖 ≥80% + 表格/代码结构化承载 ≥10 行 + 逐单元中位 ≥40%」三条件才放行（题库聚合类场景），缺一即 FAIL；**<30% 绝对红线**，任何聚合形式都不合理，直接 FAIL。去重合并场景阈值切换 65%（配置 `expansion_ratio.dedup`）。
- **`--src` fail-closed**：传了 `--src` 但文件不存在 → 直接 FAIL 拒绝放行（防止"对账被静默跳过报 100%"的假 PASS；2026-09-20 修复）。
- 再调 `glm_quality(rewritten)` 看问题清单；调 `glm_score(rewritten)` 看分数。
- 我复核：区分"真问题"（缺失/错误 → 修）vs"噪音"（措辞/分数波动/素材外增强建议 → 忽略）。
- **判定标准（机器说了算，不靠自觉）**：机械对账 <90% / 6 件套不全 / 费曼示范 <2 / 丰富度不达标（膨胀率三区间）/ 评分 <90 → 不达标；术语变体仅提示，不进判定。

### 第 8 步 · 打回循环（强制，每块独立 ≤4 次）
- 不达标 → 按 `gate_check` 问题清单 + 质检问题**针对性修补**（不整块重做）→ 回第 7 步再跑 gate_check 再验。
- 每块独立 ≤4 次；第 4 次仍不过 → **挂起**：当前稿 + 问题清单留待人工，不再自动重写。
- 各块额度独立，互不挤占。**通过 = gate_check 全绿，不是我"觉得行了"。**

### 第 9 步 · 我通读整篇整体审
- 所有块完成后，我通读整篇：前后连贯 / 有无重复 / 有无遗漏 / 知识点归位是否合理 → 有则修。

### 第 10 步 · 输出
- 调 `write_output(note_text, source_text, out_dir)`：
  - 笔记写 `out_dir/note.md`
  - **源数据外置对象 = 工作流输入的原文全文**（若输入 `_clean.md` 时间轴交错 md，则外置其完整内容，含时间锚/画面 OCR，供溯源）；写 `out_dir/源数据/转写.md`。重排主体用语音主体（gate_check 自动抽 🎤 作对账基准），但外置保留原始完整输入，不丢画面信息
- 完成后告知用户笔记位置 + 质检摘要（哪些问题已修/哪些挂起）。

---

## 防呆要点

- **不死循环**：每块 ≤4 次修补，超限挂起。
- **不修没**：机械对账（覆盖率 ≥90%）硬兜底 + 事实信息原样保留。
- **不偷工**：丰富度膨胀率硬判定（三区间 + 聚合豁免三条件，v0.4.5）——「把推导压缩成提词卡」过不了门禁，打回展开重写。
- **不割裂**：每块带全局地图 + 前后文，最后整体审。
- **附录外置**：转写原文不进笔记，源文件单独存。
